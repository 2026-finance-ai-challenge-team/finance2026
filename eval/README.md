# 검증 하네스

파이프라인이 **"이거 부족해요"를 제대로 말하는지** 자동으로 채점한다.
서비스 코드가 아니라 바깥에서 파이프라인을 두드리는 도구다.

대상 조합은 **하나은행 / 법인계좌 개설 / 대면 / 본인** 하나뿐이다.

## 왜 정확도를 안 보나

가장 위험한 실패는 부족한데 부족하다고 안 하는 것이다. 사용자가 그 말을 믿고
은행에 갔다가 거절당한다. 반대로 과잉 요구는 서류 한 장 더 떼면 끝이다.

그래서 전체 정확도가 아니라 **틀린 방향**을 센다. 아래 넷은 하나만 나와도 종료 코드 1이다.

| 치명 | 왜 |
|---|---|
| 부족 미탐지 | 사용자가 빠진 걸 모른 채 은행에 간다 |
| 실패 → 불필요 | 못 알아본 문서를 `이번 업무에는 불필요`로 내보내면 필수 서류가 조용히 빠진다 |
| 유사쌍 혼동 | 낸 적 없는 서류를 냈다고 세게 된다 |
| 실행 중 예외 | 결과를 못 준다 |

과잉 요구는 `[과잉]`으로 기록만 하고 종료 코드에 넣지 않는다.

## 지표

| 지표 | 계산 | 목표 |
|---|---|---|
| 거짓 준비완료율 | (부족한데 통과라 한 케이스) / 전체 시나리오 | 0% |
| 누락 탐지 재현율 | (빠진 걸 잡아낸 수) / (실제 빠진 수) | 100% |
| 채널 민감도 | (입력 바꿨을 때 결과가 달라진 수) / (달라져야 할 수) | 100% |
| 출처 커버리지 | (source_url + checked_at 채워진 규칙) / 전체 규칙 | 100% |
| 링크 유효율 | (200 응답 링크) / 전체 링크 | 100% |
| 분류 정확도 | 맞힌 문서 / 전체 문서 | 참고 |

지금 `evaluate.py`가 실제로 내는 건 위에서 셋이다 — 거짓 준비완료율(`[치명] 부족 미탐지`),
누락 탐지 재현율, 분류 정확도.

나머지 셋은 아직 못 센다. 출처 커버리지는 DB가 안 붙었고, 채널 민감도는 조합이 하나뿐이라
비교 대상이 없으며, 링크 유효율은 발급 경로가 확정되기 전이다. 못 센 지표는 100%로 적지 않고
`미측정`으로 출력한다.

## 설치

```bash
pip install -r requirements.txt
python -m playwright install chromium     # 최초 1회
```

## 실행

```bash
python generate.py          # 합성 PDF 14종 + labels.csv
bash   degrade.sh           # 스캔·기울어짐·저조도·흐림 이미지 + 1쪽만 스캔본인 PDF
python make_scenarios.py    # scenarios.csv
python evaluate.py          # 채점 → reports/YYYY-MM-DD.md
```

`generate.py --as-of 2026-09-01`처럼 기준일을 줄 수 있다. 문서 날짜를 전부 기준일에서
역산하므로 시간이 지나도 "1년 지난 등기부"가 계속 1년 지난 상태로 남는다.

파이프라인이 아직 없으면 `evaluate.py`는 종료 코드 2로 멈춘다. 채점기 자체만 보려면
`python evaluate.py --adapter demo` — 정답표를 되돌려주는 가짜다. 숫자를 성능으로 읽지 않는다.

## 폴더

```
eval/
├── generate.py        템플릿 → PDF + labels.csv
├── degrade.sh         degrade.py를 부르는 껍데기
├── degrade.py         이미지 변형 + 1쪽만 스캔본인 PDF
├── make_scenarios.py  scenarios.csv (하나씩 빼기 자동 + 함정 수동)
├── evaluate.py        채점기
├── requirements.txt
├── templates/         문서 HTML
├── samples/           생성 결과
├── example_file/      서식 참고용 실물 — 커밋 금지
├── docs/              맥락 문서와 작업 지시서
├── labels.csv         자동 생성
├── scenarios.csv      자동 생성 + 손으로 함정 추가
└── reports/           일자별 결과
```

`generate.py`는 렌더한 PDF를 다시 열어 앵커 문자열·제목 크기·제목 위치를 스스로 확인한다.
샘플이 잘못돼서 분류가 틀린 경우와 분류기가 틀린 경우를 구분하기 위해서다.

`templates/`의 자간은 전부 CSS로 준다. 실제 증명서처럼 `사 업 자 등 록 증`으로 보이지만
추출 텍스트는 `사업자등록증`이다. 글자 사이에 공백을 직접 넣으면 앵커가 깨진다.

`samples/`는 전부 가짜 법인이다. `example_file/`은 실제 법인 정보가 들어 있어 `.gitignore`에 있다.

## 어댑터

파이프라인 호출 방식이 확정되지 않아 `evaluate.py`의 어댑터 구간만 갈아끼우면 되게 해 뒀다.
`--adapter auto`는 import → CLI → HTTP 순으로 찾는다. 여기서 웹 서버를 띄우지는 않는다.

```python
def classify_one(path) -> {"doc_type": str|None, "confidence": float, "relevance": str}
def judge(paths)      -> {"missing": [...], "expired": [...], "accepted": [...], "notes": [...]}
```

`accepted`는 선택 항목이지만 없으면 중복 계수(t5)를 못 본다.

## 팀에 확인할 것

- **필수 목록이 하드코딩 폴백이다.** `EVAL_DB_URL`이 없어 DB를 못 읽었다. 지금 표는
  규칙 변경을 반영하지 못한다. `make_scenarios.py`의 `TODO(swap)` 블록.
- **`법인등록번호` 앵커가 실물 서식에 없다.** 등기사항전부증명서 표기는 `등록번호`다.
  샘플은 실물대로 뒀고 `generate.py`가 매번 이 사실을 출력한다.
- **법인인감증명서 제목은 `인감증명서`다.** 실물에 `법인인감증명서`는 하단 안내문에만 나온다.
  개인인감증명서와 제목이 같아서, 둘을 가르려면 `법인등록번호`·`상호`·`본점`을 봐야 한다.
  negative pair 3번이 성립하려면 이 상태여야 해서 제목을 지시서와 다르게 뒀다.
- **출처 커버리지는 미측정이다.** DB가 붙기 전까지 100%라고 쓰지 않는다.
- 위임장은 현재 범위(본인 방문)에서는 필요 없지만 10종에 있어 생성만 해 뒀다.
  대리인 조합이 생기면 그때 시나리오에 넣는다.
