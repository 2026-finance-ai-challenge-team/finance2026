# 검증 하네스

파이프라인이 **"이거 부족해요"를 제대로 말하는지** 자동 채점.
서비스 코드가 아니라 바깥에서 파이프라인을 두드리는 도구.

대상: **하나은행 / 법인계좌 개설 / 대면 / 본인** 조합 하나.

## 왜 정확도를 안 보나

가장 위험한 실패는 부족한데 부족하다고 안 하는 것. 사용자가 그 말을 믿고 은행에 갔다가 거절.
반대인 과잉 요구는 서류 한 장 추가 발급으로 해결.

그래서 전체 정확도 대신 **틀린 방향**을 계수. 아래 넷은 1건이라도 나오면 종료 코드 1.

| 치명 | 이유 |
|---|---|
| 부족 미탐지 | 사용자가 누락을 모른 채 은행 방문 |
| 실패 → 불필요 | 못 알아본 문서를 `이번 업무에는 불필요`로 내보내면 필수 서류가 조용히 누락 |
| 유사쌍 혼동 | 낸 적 없는 서류를 냈다고 계수 |
| 실행 중 예외 | 결과 미출력 |

과잉 요구는 `[과잉]`으로 기록만 하고 종료 코드에서 제외.

## 지표

| 지표 | 계산 | 목표 |
|---|---|---|
| 거짓 준비완료율 | (부족한데 통과라 한 케이스) / 전체 시나리오 | 0% |
| 누락 탐지 재현율 | (빠진 걸 잡아낸 수) / (실제 빠진 수) | 100% |
| 채널 민감도 | (입력 바꿨을 때 결과가 달라진 수) / (달라져야 할 수) | 100% |
| 출처 커버리지 | (source_url + checked_at 채워진 규칙) / 전체 규칙 | 100% |
| 링크 유효율 | (200 응답 링크) / 전체 링크 | 100% |
| 분류 정확도 | 맞힌 문서 / 전체 문서 | 참고 |

현재 `evaluate.py`가 실제로 내는 것은 셋 — 거짓 준비완료율(`[치명] 부족 미탐지`),
누락 탐지 재현율, 분류 정확도.

나머지 셋은 미측정. 출처 커버리지는 DB 미연결, 채널 민감도는 조합이 하나뿐이라 비교 대상
없음, 링크 유효율은 발급 경로 미확정. 못 센 지표는 100%로 적지 않고 `미측정`으로 출력.

## 설치

```bash
pip install -r requirements.txt
python -m playwright install chromium     # 최초 1회
```

## 실행

```bash
python tools/generate.py        # 합성 PDF 14종 + labels.csv
python tools/degrade.py         # 이미지 변형 + 1쪽만 스캔본인 PDF
python tools/make_scenarios.py  # scenarios.csv
python tools/evaluate.py        # 채점 → reports/YYYY-MM-DD.md
```

매일 돌리는 건 마지막 하나. 앞의 셋은 템플릿이나 요건이 바뀔 때만.

`generate.py --as-of 2026-09-01`로 기준일 지정 가능. 문서 날짜를 기준일에서 역산하므로
시간이 지나도 "1년 지난 등기부"는 계속 1년 지난 상태 유지.

파이프라인 미연결 시 `evaluate.py`는 종료 코드 2로 중단. 채점기만 확인하려면
`--adapter demo` — 정답표를 되돌려주는 가짜. 숫자를 성능으로 읽지 말 것.

## 폴더

```
eval/
├── tools/
│   ├── generate.py        템플릿 → PDF + labels.csv
│   ├── degrade.py         이미지 변형 + 1쪽만 스캔본인 PDF
│   ├── make_scenarios.py  scenarios.csv
│   └── evaluate.py        채점기
├── templates/             문서 HTML
├── data/
│   ├── labels.csv         자동 생성
│   ├── scenarios.csv      자동 생성 + 손으로 함정 추가
│   └── samples/           생성 결과
├── docs/                  맥락 문서와 작업 지시서
├── reports/               일자별 결과
└── example_file/          서식 참고용 실물 — 커밋 금지
```

`generate.py`는 렌더한 PDF를 다시 열어 앵커 문자열·제목 크기·제목 위치를 자체 확인.
샘플 결함과 분류기 결함을 구분하기 위한 장치.

`templates/`의 자간은 전부 CSS. 실제 증명서처럼 `사 업 자 등 록 증`으로 보이지만 추출
텍스트는 `사업자등록증`. 글자 사이에 공백을 직접 넣으면 앵커 파손.

`data/samples/`는 전부 가짜 법인. `example_file/`은 실제 법인 정보 포함이라 `.gitignore` 대상.

## 어댑터

파이프라인 호출 방식 미확정. `evaluate.py`의 어댑터 구간만 교체하면 되게 격리.
`--adapter auto`는 import → CLI → HTTP 순으로 탐색. 웹 서버 기동 없음.

```python
def classify_one(path) -> {"doc_type": str|None, "confidence": float, "relevance": str}
def judge(paths)      -> {"missing": [...], "expired": [...], "accepted": [...], "notes": [...]}
```

`accepted`는 선택 항목. 없으면 중복 계수(t5) 확인 불가.

## 팀에 확인할 것

- **필수 목록이 하드코딩 폴백.** `EVAL_DB_URL` 없어 DB 미연결. 지금 표는 규칙 변경 미반영.
  `make_scenarios.py`의 `TODO(swap)` 블록.
- **`법인등록번호` 앵커가 실물 서식에 없음.** 등기사항전부증명서 표기는 `등록번호`.
  샘플은 실물대로 두고 `generate.py`가 매번 이 사실을 출력.
- **법인인감증명서 제목은 `인감증명서`.** 실물에서 `법인인감증명서`는 하단 안내문에만 등장.
  개인인감증명서와 제목이 같아 구분하려면 `법인등록번호`·`상호`·`본점` 확인 필요.
  negative pair 3번 성립 조건이라 제목을 지시서와 다르게 유지.
- **출처 커버리지 미측정.** DB 연결 전까지 100%로 표기 금지.
- 위임장은 현재 범위(본인 방문)에서 불필요하지만 10종에 포함되어 생성만. 대리인 조합
  추가 시 시나리오에 편입.
