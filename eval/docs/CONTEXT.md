# ProofBridge — 프로젝트 개요

> Claude Code용 맥락 문서. 작업 지시는 `eval/TASK.md` 참고.

## 무엇을 만드나

**은행과 업무를 고르면 필요한 서류를 알려주고, 이미 가진 파일이 그 요건에 맞는지 대조해주는 웹서비스.**

```
입력   은행 · 업무 · 채널  (+ 가진 파일)
출력   필요 서류 목록 + 발급 경로 + (파일 있으면) 적합 판정
```

서류를 **발급**하지 않는다 — 정부24·기관이 한다.
서류를 **접수**하지 않는다 — 은행이 한다.
그 사이 빈칸, **"내가 가진 게 통하나?"** 만 채운다.

**준비 완료 ≠ 제출 완료 ≠ 승인 완료.**
"공개 기준으로 사전 점검이 끝났다"는 뜻이지 은행 승인 보장이 아니다.

## 현재 범위

하나은행 / 법인계좌 개설 / 대면 / 본인 — 조합 하나만.

## 파이프라인

```
브라우저 업로드
   ↓
로컬 브리지 (Vite)        ← 배포용 API는 아직 없음
   ↓
Python 파이프라인
   ├── 문서 분류 모듈      형식 판별 → 텍스트 확보 → 신호 수집 → 시그니처 대조 → AI
   └── 요건 판정          DB 요건과 대조 → 부족·기한·대체·원본
   ↓
준비 키트 초안 + 임시파일 삭제
```

- **분류 모듈은 판정을 하지 않는다.** 문서 종류만 정한다.
- **내용 필드(명의·주소·소득)를 뽑지 않는다.** "이게 사업자등록증인가"만 알면 된다.
  개인정보 접촉면을 모듈 경계로 줄이는 게 설계의 핵심.
- OCR은 옵트인. 텍스트 레이어가 있으면 pypdf로 끝내고, 없는 **페이지만** CLOVA 호출. 캐시 있음.
- 기한 기준은 문서 사전이 아니라 `requirement_documents.issued_within_days`.
  같은 문서도 업무·채널에 따라 인정 기간이 다르다.

## 역할

| 담당 | 범위 |
|---|---|
| 영민 | 파이프라인 |
| 연우 | 문서 판독 모듈 |
| 찬형 | 크롤링 + 규칙 DB |
| **찬우** | **검증 + 합성 데이터셋** ← 이 저장소 작업 |

## 검증이 왜 필요한가

가장 위험한 실패는 **부족한데 부족하다고 안 하는 것**이다.
사용자가 그 말을 믿고 은행에 갔다가 거절당한다.

반대(과잉 요구)는 서류 하나 더 떼는 것뿐이라 훨씬 덜 심각하다.
→ **전체 정확도가 아니라 틀린 방향을 본다.**

특히 분류 실패를 `불필요`로 내보내면 필수 서류가 조용히 빠진다.
`판단 불가`와 `이번 업무에는 불필요`는 절대 같은 값으로 나가면 안 된다.

## 검증 4층

| | 확인 | 자동화 |
|---|---|---|
| Q1 | 필요 목록이 맞나 | 불가 — 은행 공지와 사람이 대조. 보조로 출처 커버리지 |
| Q2 | 입력 바꾸면 목록도 바뀌나 | 지금은 조합이 하나뿐이라 범위 밖 |
| Q3 | 발급 링크가 실제로 되나 | 가능 |
| Q4 | 파일 넣으면 목록이 올바르게 줄어드나 | 가능 ← **지금 주력** |
